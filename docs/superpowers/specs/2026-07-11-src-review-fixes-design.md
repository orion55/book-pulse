# Исправление дефектов `src`: дизайн

## Цель

Исправить пять дефектов, найденных при ревью `src`: неполный HTTP-таймаут,
неатомарную запись результата синхронизации, ложное Telegram-уведомление при
критической ошибке, накопление временных обложек и дубликаты книг.

## Ограничения

- Успешно опубликованные книги сохраняются в БД, даже если публикация другой
  книги завершилась ошибкой.
- Неуспешные книги не сохраняются и повторяются при следующем запуске.
- Новые зависимости времени выполнения не добавляются.
- Регрессионные тесты используют встроенный `node:test`.
- Текущая последовательная отправка книг в Telegram сохраняется.

## Синхронизация данных

`dataSync` перестаёт изменять таблицу `Books`. Она читает текущее состояние и
возвращает объект-план с двумя коллекциями:

- `newBooks`: новые книги с `authorId`, предназначенные для публикации;
- `bookIdsToRemove`: первичные ключи записей, которых больше нет в успешно
  загруженных библиотеках авторов.

Пустой план возвращается как объект с пустыми массивами, а не `null`, чтобы
результат имел единообразную форму.

После последовательной обработки `newBooks` главный процесс передаёт успешно
опубликованные книги и `bookIdsToRemove` в функцию фиксации. Она выполняет одну
Prisma-транзакцию: удаляет устаревшие записи и добавляет успешно опубликованные.
Таким образом, БД не меняется до окончания внешних операций, а отдельная
неуспешная книга остаётся кандидатом следующего запуска.

Если новых книг нет, устаревшие записи всё равно должны быть зафиксированы до
отправки обычного сообщения «новых книг нет». Если фиксация БД завершается
ошибкой, обычное сообщение не отправляется, а применяется обработка критической
ошибки.

## Защита от дубликатов

В Prisma-модели добавляется составное ограничение
`@@unique([authorId, bookId])`. Миграция сначала удаляет существующие повторные
строки, сохраняя запись с минимальным `id`, затем создаёт уникальный индекс.

Парсер книг дедуплицирует ссылки по `bookId`, сохраняя первое вхождение и его
заголовок. Это предотвращает лишнюю работу ещё до обращения к БД. В транзакции
каждая успешно отправленная книга записывается через `upsert` по составному
ключу. Повторная или конкурентная фиксация поэтому не создаёт дубликат.

## HTTP-таймаут

`fetchHtmlWithRetry` сохраняет `AbortController` активным до завершения
`response.text()`. Таймер очищается в `finally` для каждого запроса — при
успехе, HTTP-ошибке, ошибке чтения тела или abort. Поэтому зависание после
получения заголовков также заканчивается ошибкой текущей попытки и обычным
retry/backoff.

Для тестирования функция получает необязательный объект зависимостей с `fetch`,
`setTimeout`, `clearTimeout` и `sleep`; по умолчанию используются глобальные
реализации. Публичное поведение производственного вызова не меняется.

## Telegram и временные файлы

Критическая ошибка отправляется отдельной функцией уведомления с явным текстом
о сбое проверки. Она не переиспользует `sendMessage(null, ...)`, поэтому
пользователь не получает ложное сообщение «новых книг нет». Исходная ошибка
всегда логируется первой; ошибка самого уведомления логируется отдельно и не
заменяет исходную.

Для каждой книги путь загруженной обложки считается временным ресурсом.
`sendMessage` удаляет читаемый файл в `finally`, независимо от того, завершилась
ли отправка фотографии или текста успешно. Ошибка удаления логируется, но не
меняет результат отправки. Отсутствующий или нечитаемый путь не удаляется.

## Тестирование

В `devDependencies` явно добавляется `tsx`, а в `package.json` — команда
`test`, запускающая TypeScript-тесты через `tsx` и `node:test`. Новая зависимость
используется только при разработке. Регрессионные тесты покрывают:

1. abort во время чтения тела ответа и очистку таймера;
2. отсутствие изменений БД на стадии вычисления плана;
3. одну транзакцию для удаления и добавления только успешных книг;
4. фиксацию удалений при отсутствии новых книг;
5. отдельное критическое Telegram-уведомление и сбой его отправки;
6. удаление обложки при успешной и неуспешной отправке;
7. дедупликацию одинаковых `bookId` в HTML;
8. уникальность `(authorId, bookId)` на уровне SQLite/Prisma.

Итоговая проверка включает `npm test`, `npx tsc --noEmit`, `npm run lint` и
`npm run generate-clients` после изменения Prisma-схемы.

## Не входит в работу

- Параллельная отправка книг в Telegram.
- Очередь заданий или отдельные статусы публикации в БД.
- Изменение формата `config.yml`.
- Общий рефакторинг сервисов за пределами пяти исправлений.
